Three-file leaf module split by concern: `help_bot_runner.py` is the CLI entrypoint that parses args (`--simulate`, `--from-pipeline`, `--mode mic|replay`, `--prewarm-tts`, `--verify-tts`), builds incidents via `slice_runner` (Module 1 integration), and dispatches to either replay or live mic mode. `services/help_bot_service.py` implements the state machine (`HelpBotSession`) with states `initial_guidance -> ongoing_monitor -> escalated_monitor`, plus provider-boundary functions for STT (`gemini_transcribe_responder` / `dashscope_transcribe_responder`), intent detection (`detectResponderIntent` using a strict JSON classifier prompt), and TTS (`speakGuidance` with disk cache under `mockdata/helpbot/tts_cache`). Content is isolated in `services/help_bot_content.py` as pure data (`BRANCHES`, `SHARED_LINES`) so the engine never composes medical text. Provider selection is delegated to `slice_runner._ai_provider()` so Gemini/DashScope implementations are swapped behind identical interfaces. Escalation flows through a single `escalateIncident()` hook that upgrades severity tier, merges flags, flags BHU/ambulance, and appends transitions to the incident record, keeping Module 3/8 wiring clean. Audio I/O (`MicMonitor`, `play_wav`) uses lazy imports of `sounddevice`/`numpy` so replay runs work headless; barge-in is implemented via energy VAD on a continuous mic stream.
