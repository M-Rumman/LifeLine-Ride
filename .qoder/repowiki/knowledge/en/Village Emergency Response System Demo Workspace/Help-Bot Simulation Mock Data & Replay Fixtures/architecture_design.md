The module is a flat fixture store consumed by the LifeLine help-bot test harness, organized into two top-level areas. `helpbot/scripts/*.json` declare scenario definitions — each file has a `title` describing the intended flow and a `turns` array where every turn specifies `kind`, an Urdu `urdu` transcript, and an `expect` intent label (`step_done`, `in_scope_question`, `out_of_scope`, `escalation`) that drives branch matching in the bot engine. `helpbot/test_runs/*.json` are full replay artifacts produced by running those scripts; they share a fixed schema with top-level keys `run_kind`, `script_title`, `incident_id`, `branch_id`, `provider`, `started_at`/`finalized_at`, `turns`, `expectations` (with `transcript`, `expected`, `actual`, `match`), `latencies` (per-turn `detect_ms`/`respond_ms`/`turn_wall_ms`), `help_bot_transitions` (uniform `{timestamp, branch, from_state, to_state, trigger_type, detail}` entries using triggers like `branch_entered`, `step_started`, `in_scope_question`, `out_of_scope_question`, `escalation_triggered`, `session_finalized`), and `final_incident` (including severity tier, injury flags, and a copy of transitions). `helpbot/tts_cache/manifest.json` maps SHA1-hashed `.wav` filenames to Gemini TTS model/voice/text metadata so rendered audio remains reproducible; the WAV files themselves live alongside it. `media/` provides reusable inputs: paired `*.txt` + `*.mp3` voice clips under `voice/` (e.g. snakebite, taang, ungli) used as simulated user input, placeholder PNG photos under `photos/`, and a `.triage_cache/` directory for triage tooling artifacts. There is no executable code here — the JSON schemas in `scripts/` and `test_runs/` form the contract between the simulator and the help-bot engine.
