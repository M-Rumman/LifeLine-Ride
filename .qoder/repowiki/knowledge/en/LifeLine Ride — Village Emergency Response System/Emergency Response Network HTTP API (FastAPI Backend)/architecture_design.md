Three-layer layout inside `backend/`: `main.py` is the FastAPI entrypoint that wires the app, mounts the `/api/v1` router from `routes/emergency.py`, serves cached media via `StaticFiles`, and runs a `lifespan` hook calling `bootstrap_responder_state()` which seeds missing responders, loads persisted availability into `SEED_RESPONDERS`, rehydrates `INCIDENT_STORE` from DB, and releases orphaned busy responders — every step non-fatal so the app boots without PostgreSQL. `routes/emergency.py` is a pure controller: Pydantic request models validate payloads, helpers like `_require_open_record` enforce business invariants, and each endpoint delegates to `services/*`. Domain contracts (`Incident`, `Responder`, `BHU`, `DispatchResult`, `GPSLocation`) live in `slice_runner.py`, which also hosts the swappable AI provider boundary (`gemini_*` / `dashscope_*` selected by `TRIAGE_AI_PROVIDER`) and the Module 1 triage pipeline. Stateful help-bot sessions are kept in-process in `_HELPBOT_SESSIONS` keyed by `incident_id` and advanced across requests. Persistence lives under `models/` (`incident_model.py`, `responder_model.py`) using SQLAlchemy ORM against a shared `engine`/`SessionLocal` from `database.py`; JSONB columns store list/dict fields while GPS/location are flattened for queryability. Standalone scripts under `scripts/` and top-level `test_*.py` exercise individual flows without starting the server.
