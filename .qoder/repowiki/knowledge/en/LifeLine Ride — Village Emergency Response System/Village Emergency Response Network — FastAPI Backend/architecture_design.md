Three-layer layout inside `backend/`:
- Entry & bootstrap (`main.py`): creates the FastAPI app, installs CORS, mounts the `/api/v1` router from `routes/emergency.py`, serves cached media via `StaticFiles` from `mockdata/`, and runs a `lifespan` hook that calls `bootstrap_responder_state()` — seeding missing responders, loading availability status from DB (DB is authoritative), rehydrating `INCIDENT_STORE` from PostgreSQL, then releasing orphaned busy responders. Every step is wrapped in try/except so the app boots even without PostgreSQL.
- Controller layer (`routes/emergency.py`): pure Pydantic-validated request models dispatch to services; shared helpers `_fresh_record` / `_require_open_record` enforce open-incident invariants; a process-global `_HELPBOT_SESSIONS` dict holds per-incident help-bot state across requests; all errors are normalized through `install_error_handlers` into `{"code", "message"}` JSON.
- Service layer (`services/*`): domain logic split by module — `dispatch_service` (Module 3, local-only matching), `help_bot_service` (Module 2, intent detection + scripted guidance), `incident_lifecycle_service` (Module 6/6.5, close/arrival/timeline), `accountability_service` (Module 5 metrics), `matching_service`, `onboarding_service` (Module 7).
- Persistence (`models/incident_model.py`, `models/responder_model.py`): SQLAlchemy ORM against a shared `engine`/`SessionLocal` from `database.py`; JSONB columns store list/dict fields while GPS/location are flattened for queryability; idempotent upserts via `INSERT … ON CONFLICT DO UPDATE`.
- Contracts & AI boundary (`slice_runner.py`): defines `Incident`, `Responder`, `BHU`, `DispatchResult`, `GPSLocation` Pydantic models plus seed data (`SEED_RESPONDERS`, `SEED_BHUS`, `INCIDENT_STORE`); hosts the swappable AI provider boundary (`gemini_*` / `dashscope_*` selected by `TRIAGE_AI_PROVIDER`) and Module 1 triage pipeline with disk-cached outputs under `mockdata/media/.triage_cache` keyed by photo+voice hash.
Dependency direction: routes → services → slice_runner contracts → models → database; services never import routes, and persistence is always invoked from services or bootstrap, never directly from endpoints.
